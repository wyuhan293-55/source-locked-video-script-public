# Medical Aesthetics Compliance Gate

Use this reference for public-facing medical-aesthetics content. It is a **risk gate**, not a script template.

## 1. Channel First

Do not treat all Xiaohongshu publishing rules as the same.

```text
社区可发 != 聚光/广告可投
```

- If the user explicitly says `聚光`, `投放`, `广告`, or paid delivery, apply the stricter paid-delivery rules available in the project.
- If the channel is unknown, apply baseline public-safety rules and flag channel-sensitive wording instead of assuming it is paid-delivery eligible.
- Current project/account/platform rules override this general reference.

## 2. Risk Scan Categories

Before final delivery, scan the **title, cover copy if requested, screen text, packaging, and final spoken lines** for these categories.

### Absolute / superlative / guarantee language

Examples include:

- `最`, `第一`, `唯一`, `顶级`, `最好`
- `保证`, `百分百`, `一定`, `绝对`
- `永久`, `永不`, `零风险`, `无副作用`

Do not convert a single case or doctor opinion into a universal guarantee.

### Unsupported efficacy or recovery promises

Examples include claims equivalent to:

- guaranteed improvement
- guaranteed naturalness
- guaranteed no scar / no swelling / no recovery period
- a fixed recovery result for everyone

Keep outcome language case-bound, observable, and source-supported.

### Individual diagnosis / forced decision language

Be cautious with wording equivalent to:

- `你就是...`
- `你一定适合...`
- `你必须做...`
- `这种情况肯定要...`

Prefer condition-based judgment: what variables need to be checked, what this case shows, and where individual assessment is still required.

### Authority / credential overclaim

Be cautious with:

- `权威`, `顶尖`, `第一`, `唯一`, `专家`, `鼻王/眼王` and similar authority pressure

Only use credentials that are verified, relevant, and allowed for the target channel. Do not turn credentials into outcome guarantees.

### Competitor comparison / denigration

Do not use unsupported claims such as:

- other doctors cannot do it
- this method is better than all others
- competitor work is inferior

Use the doctor's own judgment standard, tradeoff, or technique instead of attacking alternatives.

### Hard conversion / off-platform diversion

Do not invent or automatically add hard CTAs.

Risk examples include:

- adding WeChat / phone / external contact information
- off-platform diversion
- platform-disallowed `私信`, `预约`, `立即咨询` or transaction-pressure wording

CTA permissions are channel- and account-dependent. Use only the current project's approved wording when available.

### Case / result / recovery proof

- Do not fabricate, exaggerate, or AI-enhance a result and present it as real proof.
- Do not turn one person's result or recovery into a universal expectation.
- Before/after, testimonials, recovery claims, and case proof may have stricter paid-delivery rules than community publishing.

## 3. Local Hard Blacklist

Some projects or delivery channels maintain a hard blacklist of ordinary-looking words. Examples may include terms such as `医生`, `手术`, `面诊`, `患者`, specific CTA words, project names, or procedure terms.

Do **not** treat these examples as universal bans. Instead:

1. Load the current project/account compliance rules if available.
2. Treat their blacklist as authoritative for that delivery target.
3. Scan the final public-facing script against that blacklist.

## 4. Source-Locked Handling Of Risky Words

Never make risky source audio look compliant by silently rewriting what the speaker said.

If a selected source fragment contains a disallowed term for the target channel:

1. Prefer another source fragment that carries the same useful meaning.
2. Otherwise omit the risky fragment from the public final cut.
3. If needed, use clearly labeled non-source packaging with safer wording.
4. If the core claim itself is not allowed or not supported, mark the topic `不建议出稿` for that channel.

The source archive may contain risky wording; the **final selected source table should contain only audio intended for the target public cut**.

## 5. Final Compliance Question

Before delivery ask:

```text
Is this claim true and source-supported?
Is it allowed for this exact channel/account?
Does it pressure, guarantee, diagnose, compare, or divert more than necessary?
```

If any answer is uncertain, narrow or flag it instead of inventing certainty.
